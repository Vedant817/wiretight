Step 1 continued: the Quotes approach allows retrieving a guaranteed, locked-in rate valid for a specified period (1 minute up to 24 hours). The returned `quote_id` must be used in the subsequent conversion or payout request before the quote expires.

### Quotes

To retrieve a guaranteed quote for use within a validity period, call [Create a Quote](https://www.airwallex.com/docs/api/transactional_fx/quotes/create.md). Specify the `buy_currency`, `sell_currency`, `buy_amount`/`sell_amount`, and the quote `validity`. Supported validity periods include: 1 minute, 15 minutes, 30 minutes, 1 hour, 4 hour, 8 hour, 24 hour.

Optionally, you can specify a `conversion_date`, i.e., the date on which the conversion will be settled. If you do not specify a date, Airwallex determines the default based on your funding mode (see [settlement timing](https://www.airwallex.com/docs/transactional-fx/funding-and-settlement-models.md#settlement-timing)).

Once a quote is retrieved, you must request a conversion using that quote before the expiry time (`valid_to_at`) returned in the response.

### Example request

```shell
curl -X POST https://api.sandbox.airwallex.com/api/v1/fx/quotes/create \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer {{ACCESS_TOKEN}}' \
  -d '{
    "buy_amount": "10000",
    "buy_currency": "USD",
    "conversion_date": "2024-03-22",
    "sell_currency": "AUD",
    "validity": "HR_24"
  }'
```

A successful conversion returns the `quote_id` in the response. You must store the `quote_id` for future use on subsequent conversions or payout requests (see [Create a payout](https://www.airwallex.com/docs/payouts/transfers/create-a-transfer.md#step-2-create-a-transfer)).

The quote response also contains key details that are required for a successful subsequent conversion booking including:

- Validity period of the quote ( `valid_from_at` , `valid_to_at` )
- Quote usage (`MULTI_USE`)
- Conversion date (`conversion_date`)
- Direction of conversion (`buy_currency`, `sell_currency`)

The Create a Quote API endpoint provides a guaranteed FX rate for an agreed period of time. This reference covers the endpoint URL, authentication, request parameters, and a cURL example.

# Create a Quote

The Quote endpoint gives the user a guaranteed rate for an agreed period of time.

## Endpoint

`POST /api/v1/fx/quotes/create`

## Request Headers

- `Authorization` (string, required)
  Obtain a token via `POST /api/v1/authentication/login` with your API key and client unique identifier. Pass it as `Authorization: Bearer {{ACCESS_TOKEN}}`. Tokens expire after a configurable duration.

## Request Parameters

### Request Body

- `buy_currency` (string, required)
  Currency (3-letter ISO-4217 code) the client buys.
- `sell_currency` (string, required)
  Currency (3-letter ISO-4217 code) the client sells.  This is the currency you will need to send us by the settlement cutoff time.
- `validity` (string, required)
  Quote validity period.
  Possible values:
  - `MIN_1`
  - `MIN_15`
  - `MIN_30`
  - `HR_1`
  - `HR_4`
  - `HR_8`
  - `HR_24`
- `application_fee_options` (array[object], optional)
  The application fee options applied to the transaction.
  - `amount` (string, optional)
    A positive integer specifying the amount of the fee expressed in the smallest unit of the currency. e.g. cents for USD. This field is required only when type is FIXED.
  - `currency` (string, optional)
    Specify the currency of the application fee in ISO 4217 currency code format, e.g., USD, AUD. This field is required when the type is FIXED.
    When the type is PERCENTAGE and source_type is CONVERSION, the currency for the conversion if specified must be from the currency pair. If the currency is unspecified, the contra currency of the quote will be used.
  - `metadata` (object, optional)
    The metadata of the application fee. The value should be set in key:value format. (e.g., id:1).
  - `percentage` (string, optional)
    Required if the type is PERCENTAGE, and the value to be provided depends on the transaction context.
    FX Conversions: The value acts as a markup on the FX rate, increasing the conversion cost by the specified percentage.
    Others: The value represents a direct fee calculated as a percentage of the transaction amount.
  - `source_type` (string, optional)
    Specify type of the source transaction.
    Possible values:
    - `CONVERSION`
    - `TRANSFER`
  - `type` (string, optional)
    Define the type of fee calculation. If the `source_type` is `CONVERSION`, then the type must be `PERCENTAGE`.
    Possible values:
    - `FIXED`
    - `PERCENTAGE`
- `buy_amount` (number, optional)
  Amount the client buys in `buy_currency` (must be blank if `sell_amount` is specified).
- `conversion_date` (string, format: date, optional)
  Date on which the conversion will be settled. `conversion_date` defaults to current date, if funding is available, unless specified.
- `sell_amount` (number, optional)
  Amount the client sells in `sell_currency` (must be blank if `buy_amount` is specified).

## cURL example

```bash
curl --request POST \
  --url 'https://api.sandbox.airwallex.com/api/v1/fx/quotes/create' \
  --header 'Authorization: Bearer {{ACCESS_TOKEN}}' \
  --header 'Content-Type: application/json' \
  --data '{
  "application_fee_options": [
    {
      "amount": "5",
      "currency": "AUD",
      "percentage": "0.1",
      "source_type": "TRANSFER",
      "type": "FIXED"
    }
  ],
  "buy_amount": 10000,
  "buy_currency": "AUD",
  "conversion_date": "2017-04-01",
  "sell_amount": 100,
  "sell_currency": "USD",
  "validity": "HR_24"
}'
```

Once a conversion quote is created, it can be reused, refreshed, reset, or retrieved as needed. This chunk covers quote invalidation and refresh behavior, how to dissociate a quote from a payment intent to revert to the original currency, and how to retrieve an existing quote by ID.

### Quote invalidation and refresh

A quote can be reused by multiple payment intents, as long as it is within its validity period. We use the `expires_at` timestamp to mark the quote's expiration time. Upon expiry, a quote's `status` attribute changes to `EXPIRED`.

Merchants need to call the [create quote API](#step-2-create-a-conversion-quote) to refresh and replace the quote before it expires. This can be done either in real time during shopper interactions or periodically via scheduled tasks.

Whenever feasible, we encourage you to reuse an existing valid quote that matches the source and target currency for a particular payment. This will minimize latency for your shoppers.

### Reset payment intent to original currency

To dissociate a quote from a payment intent and revert the payment intent to its original currency, make the following API call to update the quote with a null quote ID.

Request:

```shell
curl -X POST https://api.sandbox.airwallex.com/api/v1/pa/payment_intents/int_hkpdskz7vg1xc7uscdj/update \
  -H 'Authorization: Bearer {{ACCESS_TOKEN}}' \
  -H 'Content-Type: application/json' \
  -d '{
    "request_id": "28f0a16f-4e97-4d77-a310-3cf7be2ba6ed",
    "conversion_quote_id": null
  }'
```

Response:

```json
{
  "id": "int_hkpdskz7vg1xc7uscdj",
  "amount": 100,
  "currency": "EUR",
  ...,
}
```

  - `rate` (number, optional)

  - `sell_amount` (number, optional)

Airwallex's Quotes API allows you to create and retrieve FX quotes that can be used in subsequent conversion requests within a specified validity period.

# Quotes

Create a quote that can be used in a subsequent conversion request during the requested validity period.

## Endpoints

- [Create a Quote](https://www.airwallex.com/docs/api/transactional_fx/quotes/create.md) — `POST /api/v1/fx/quotes/create`
- [Retrieve a Quote](https://www.airwallex.com/docs/api/transactional_fx/quotes/retrieve.md) — `GET /api/v1/fx/quotes/{quote_id}`

The `POST /api/v1/batch_transfers/{id}/quote` endpoint locks FX rates for a batch transfer. Only valid items in the batch are quoted, and quoting is only permitted when the batch status is `DRAFTING` or `IN_APPROVAL`.

# Quote a Batch Transfer

After adding valid transfer items to the batch, you can quote/lock FX rates by specifying the batch transfer `id`. Please note that only valid items in the batch will be quoted; you can only quote a batch transfer when its status is `DRAFTING` or `IN_APPROVAL`.

## Endpoint

`POST /api/v1/batch_transfers/{id}/quote`

## Request Headers

- `Authorization` (string, required)
  Obtain a token via `POST /api/v1/authentication/login` with your API key and client unique identifier. Pass it as `Authorization: Bearer {{ACCESS_TOKEN}}`. Tokens expire after a configurable duration.

## Request Parameters

### Path Parameters

- `id` (string, format: uuid, required)
  Unique identifier of the batch transfer to quote.

### Request Body

- `validity` (string, optional)
  Quote validity period.. The value will default to MIN_1 if not specified.
  Possible values:
  - `MIN_1`
  - `MIN_15`
  - `MIN_30`
  - `HR_1`
  - `HR_4`
  - `HR_8`
  - `HR_24`

## cURL example

```bash
curl --request POST \
  --url 'https://api.sandbox.airwallex.com/api/v1/batch_transfers/batch_transfer_id/quote' \
  --header 'Authorization: Bearer {{ACCESS_TOKEN}}' \
  --header 'Content-Type: application/json' \
  --data '{
  "validity": "HR_24"
}'
```
