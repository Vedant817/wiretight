The Transition Transfer Status endpoint allows sandbox simulation of transfer status changes, including the endpoint definition, authentication, path and body parameters, and a cURL example.

# Transition Transfer Status

You can use this endpoint to simulate the status transition of your transfer. This is only available in the Sandbox environment. Learn about the [transfer status lifecycle](https://www.airwallex.com/docs/payouts/transfers/create-a-transfer/transfer-statuses.md).

## Endpoint

`POST /api/v1/simulation/transfers/{id}/transition`

## Request Headers

- `Authorization` (string, required)
  Obtain a token via `POST /api/v1/authentication/login` with your API key and client unique identifier. Pass it as `Authorization: Bearer {{ACCESS_TOKEN}}`. Tokens expire after a configurable duration.
- `x-api-version` (string, optional)
  x-api-version.

## Request Parameters

### Path Parameters

- `id` (string, format: uuid, required)
  Unique identifier of the transfer to transition the status of.

### Request Body

- `next_status` (string, required)
  The next status to transition to. Status can be OVERDUE, PROCESSING, SENT, PAID, FAILED, and CANCELLED.
- `failure_type` (string, optional)
  The type of failure to simulate.
  Possible values:
  - `ACCOUNT_CLOSED`
  - `ACCOUNT_CURRENCY_MISMATCH`
  - `ACCOUNT_INACTIVE_OR_DORMANT`
  - `ACCOUNT_UNDER_RESTRICTION`
  - `BENEFICIARY_BANK_RETURNED`
  - `BENEFICIARY_NAME_MISMATCH`
  - `BENEFICIARY_REQUESTED`
  - `CARD_ISSUER_ERROR`
  - `CHANNEL_POLICY`
  - `CHANNEL_TIMEOUT`
  - `CLIENT_REQUESTED`
  - `DUPLICATION_RETURN`
  - `EXCEEDED_TRANSACTION_AMOUNT_OR_LIMIT`
  - `INBOUND_2B_CARD_NOT_SUPPORTED`
  - `INBOUND_BENFICIARY_VALIDATION_ERROR`
  - `INBOUND_COMPANY_REGISTRATION_NUMBER_ERROR`
  - `INBOUND_ORDER_ERROR`
  - `INSUFFICIENT_FUNDS`
  - `INVALID_ACCOUNT_NAME_OR_NUMBER`
  - `INVALID_BANK_INFORMATION`
  - `INVALID_BANK_OR_BRANCH_CODE`
  - `INVALID_BENEFICIARY_DETAILS`
  - `INVALID_CORRESPONDENT_BANK_INFORMATION`
  - `INVALID_PAYMENT_PURPOSE`
  - `INVALID_SPECIAL_CHARACTER`
  - `INVALID_SWIFT_BIC_CODE`
  - `OTHER`
  - `RECALL_REQUESTED`
  - `SYSTEM_ERROR`
  - `TM_SUSPENDED`
  - `TRANSACTION_AMOUNT_NOT_COVERING_FEE`
  - `UNABLE_TO_APPLY`

## cURL example

```bash
curl --request POST \
  --url 'https://api.sandbox.airwallex.com/api/v1/simulation/transfers/transfer_id/transition' \
  --header 'Authorization: Bearer {{ACCESS_TOKEN}}' \
  --header 'Content-Type: application/json' \
  --data '{
  "failure_type": "INVALID_ACCOUNT_NAME_OR_NUMBER",
  "next_status": "SENT"
}'
```

Step 3 of the simulation guide covers how to call the Transition Transfer Status endpoint to move a transfer through its status lifecycle. Behavior differs depending on the API version in use, and specific failure types can be simulated using the failure_type parameter.

## Step 3:  Transition transfer status

### API version 2024-01-31 or later

Call [Transition Transfer Status](https://www.airwallex.com/docs/api/simulation/transfers/transition.md) and specify the `transfer_id` in the endpoint URL to simulate the status transition of your transfer.

Specify the `next_status` parameter in the request body to transition your  transfer to a subsequent status. See [Transfer statuses](https://www.airwallex.com/docs/payouts/transfers/create-a-transfer/transfer-statuses.md) to understand the definition and sequence of transfer statuses.

This endpoint supports simulating these statuses: `PROCESSING`, `FAILED`, `SENT`, `PAID`, or `CANCELLED`. [Transfer statuses](https://www.airwallex.com/docs/payouts/transfers/create-a-transfer/transfer-statuses.md) that are only applicable to the transfers [created and submitted for approval](https://www.airwallex.com/docs/payouts/transfers/manage-transfers/manage-approvals-for-transfers.md) are not currently supported.

- The status can only be transitioned if the `next_status` specified is the next valid status in [Transfer statuses (old versions)](https://www.airwallex.com/docs/payouts/older-api-versions/transfers/transfer-statuses.md). Please note that `OVERDUE` can only be simulated when the transfer is not funded beyond the transfer date; `PAID` can only be simulated in API version 2024-04-30 or later.
- If you specified an invalid status name, you will receive an error message about invalid next status.
- When you use `FAILED`, please also specify a `failure_type` with an acceptable value from the table below to simulate a specific failure reason (which will be the returned `failure_reason` in the response).

### API version 2023-10-01 or earlier

Call [Transition Payment Status](https://www.airwallex.com/docs/api/2023-10-01/simulation/payouts/transition_payments.md) and specify the `payment_id` in the endpoint URL to simulate the status transition of your transfer.

Specify the `next_status` parameter in the request body to transition your  transfer to a subsequent status. See [Transfer statuses (old versions)](https://www.airwallex.com/docs/payouts/older-api-versions/transfers/transfer-statuses.md) to understand the definition and sequence of transfer statuses.

This endpoint supports simulating these statuses: `READY_FOR_DISPATCH`, `DISPATCHED`, `IN_REVIEW`, `SUSPENDED`, or `FAILED`. [Transfer statuses (old versions)](https://www.airwallex.com/docs/payouts/older-api-versions/transfers/transfer-statuses.md) that are only applicable to the transfers [created and submitted for approval](https://www.airwallex.com/docs/payouts/transfers/manage-transfers/manage-approvals-for-transfers.md) are not currently supported.

- If you use `IN_REVIEW`, `READY_FOR_DISPATCH` or `SUSPENDED`, the status can only be transitioned if it is the next valid status in [Transfer statuses (old versions)](https://www.airwallex.com/docs/payouts/older-api-versions/transfers/transfer-statuses.md).
- If you use `DISPATCHED` or `FAILED`, the status will automatically transition through intermediary statuses into the status you designate.
- When you use `FAILED`, please also specify a `failure_type` with an acceptable value from the table below to simulate a specific failure reason (which will be the returned `failure_reason` in the response).

| `failure_type` in request                   | `failure_reason` in response                       |

### Example request

```shell
curl -X POST https://api.sandbox.airwallex.com/api/v1/simulation/transfers/{{TRANSFER_ID}}/transition \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer {{ACCESS_TOKEN}}' \
  -d '{
    "next_status": "DISPATCHED"
  }'
```

Each failure reason includes a code and description, and failed transfers are automatically cancelled in seconds.

# Failure reasons

You can learn about the cause of a failure from the `failure_reason` field of a failed transfer, by either listening for the `payout.transfer.failed` [webhook event](https://www.airwallex.com/docs/developer-tools/webhooks/listen-for-webhook-events/transfers.md) or retrieving the transfer via API request ([Get transfer by ID](https://www.airwallex.com/docs/api/payouts/transfers/retrieve.md)). The `failure_reason` consists of a failure code and a failure description.

Please note that failed transfers will be automatically cancelled in seconds.

Use the table below to understand the `failure_reason` and determine the next steps to take. You can learn more in [Handle failed transfers](https://www.airwallex.com/docs/payouts/transfers/manage-transfers/handle-failed-transfers.md).

## Invalid account name/number (90101)

| **Failure Code** | **Failure Description**     |
| ---------------- | --------------------------- |
| 90101            | Invalid account name/number |

**Recommended action**: Create a new transfer with updated parameters.

## Invalid bank information (90201 - 90204)

| ---------------- | -------------------------------------- |
| 90201            | Invalid bank/branch code               |
| 90202            | Invalid SWIFT/BIC code                 |
| 90203            | Invalid correspondent bank information |
| 90204            | Invalid bank information               |

**Recommended action**: Create a new transfer with updated parameters.

## Account information mismatch (90301 - 90302)

| **Failure Code** | **Failure Description**   |
| ---------------- | ------------------------- |
| 90301            | Beneficiary name mismatch |
| 90302            | Account currency mismatch |

**Recommended action**: Create a new transfer with updated parameters.

## Invalid beneficiary details (90401 - 90402)

| **Failure Code** | **Failure Description**     |
| ---------------- | --------------------------- |
| 90401            | Invalid beneficiary details |
| 90402            | Invalid special character   |

**Recommended action**: Create a new transfer with updated parameters.

## Internal policy (90501 - 90502)

| **Failure Code** | **Failure Description** |
| ---------------- | ----------------------- |
| 90501            | Channel policy          |
| 90502            | TM suspended            |

**Recommended action**: As it cannot be processed further after internal review, after the transfer is cancelled, please create a new one with updated parameters.

## Funding error (90604)

| **Failure Code** | **Failure Description** |
| ---------------- | ----------------------- |
| 90604            | Insufficient balance    |

**Recommended action**: Please top up your wallet balance before creating the transfer again.

## Abnormal account status (90701 - 90703)

| **Failure Code** | **Failure Description**     |
| ---------------- | --------------------------- |
| 90701            | Account closed              |
| 90702            | Account inactive or dormant |
| 90703            | Account under restriction   |

**Recommended action**: Inform your beneficiary that the transfer failed due to the beneficiary account being closed/inactive/restricted.

## Beneficiary requested (90801 - 90802)

| **Failure Code** | **Failure Description**   |
| ---------------- | ------------------------- |
| 90801            | Beneficiary requested     |
| 90802            | Beneficiary bank returned |

**Recommended action**: If beneficiary bank return is unexpected, please advise your beneficiary to check with the receiving bank.

## China local transfer error (90901 - 90904, 91201)

The optional response fields for the created transfer include application fee options, conversion details, dispatch information, failure details, and metadata. HTTP error codes and their possible error types are also listed.

- `application_fee_options` (array[object], optional)
  The application fee options applied to this transfer.
  - `amount` (string, optional)
    A positive integer specifying the amount of the fee expressed in the smallest unit of the currency. e.g. cents for USD. This field is required only when type is FIXED.
  - `currency` (string, optional)
    Specify the currency of the application fee in ISO 4217 currency code format, e.g., USD, AUD. This field is required when the type is FIXED.
    When the type is PERCENTAGE and source_type is CONVERSION, the currency for the conversion if specified must be from the currency pair. If the currency is unspecified, the contra currency of the quote will be used.
  - `metadata` (object, optional)
    The metadata of the application fee. The value should be set in key:value format. (e.g., id:1).
  - `percentage` (string, optional)
    Required if the type is PERCENTAGE, and the value to be provided depends on the transaction context.
    FX Conversions: The value acts as a markup on the FX rate, increasing the conversion cost by the specified percentage.
    Others: The value represents a direct fee calculated as a percentage of the transaction amount.
  - `source_type` (string, optional)
    Specify type of the source transaction.
    Possible values:
    - `CONVERSION`
    - `TRANSFER`
  - `type` (string, optional)
    Define the type of fee calculation. If the `source_type` is `CONVERSION`, then the type must be `PERCENTAGE`.
    Possible values:
    - `FIXED`
    - `PERCENTAGE`
- `application_fees` (array[object], optional)
  Application fees in this transfer.
  - `amount` (string, optional)
    The application fee amount.
  - `currency` (string, optional)
    The currency of the application fee.
  - `source_type` (string, optional)
    Specify the type of source transaction for this application fee.
    Possible values:
    - `CONVERSION`
    - `TRANSFER`
- `batch_transfer_id` (string, optional)
  Unique identifier of the batch containing the transfer.
- `beneficiary_id` (string, format: uuid, optional)
  beneficiary_id of the beneficiary contact used to create this transfer.
- `conversion` (object, optional)
  Conversion details of a transfer with currency conversions.
  - `currency_pair` (string, required)
    The currency pair of the conversion.
  - `rate` (number, required)
    The rate of the conversion.
- `dispatch_date` (string, optional)
  Actual payout dispatch date. Payouts are dispatched at this date in actual processing. This date could be later than the transfer date.
- `dispatch_info` (object, optional)
  Additional details populated after the transaction is sent to Airwallex's downstream for processing. Only available for some transfer methods - see [Product Docs](https://www.airwallex.com/docs/payouts/transfers/create-a-transfer.md) for details.
  - `external_reference` (string, optional)
    A reference ID to track a transfer after it's dispatched from Airwallex. For stablecoin transfers, this is the on-chain transaction hash.
  - `external_reference_type` (string, optional)
    The definition of the `external_reference` in the payment system. Possible values include `NETWORK_TRANSACTION_ID` for stablecoin transfers (blockchain transaction hash).
- `failure` (object, optional)
  Failure details if the transfer is in an error state.
  - `code` (string, optional)
    Failure code.
  - `details` (object, optional)
    Additional failure details.
    - `reason_codes` (array[string], optional)
      Detailed reason code.
    - `type` (string, optional)
      Failure type.
  - `message` (string, optional)
    Failure message.
- `lock_rate_on_create` (boolean, optional)
  Denotes whether to lock the conversion rate for a scheduled transfer with value `TRUE` or `FALSE`.This field should only be specified when a conversion is involved. If not specified, the default value is `TRUE`.
- `metadata` (object, optional)
  A set of key-value pairs for storing your own data together with the transfer.
- `payer_id` (string, format: uuid, optional)
  payer_id of the payer contact used to create this transfer.
- `prepayment` (object, optional)
  Prepayment details for a schedule transfer with currency conversions at a confirmed rate.
  - `amount` (number, required)
    The prepayment amount to be paid.
  - `currency` (string, required)
    The prepayment currency.
- `remarks` (string, optional)
  Additional information about this transfer, which will not be passed to the beneficiary.
- `swift_charge_option` (string, optional)
  (For SWIFT transfers only), specify who should bear SWIFT charges, either `SHARED` (default) or `PAYER`.
