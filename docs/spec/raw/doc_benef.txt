The Update an Existing Beneficiary API allows editing a beneficiary stored on the Airwallex platform via a POST request, requiring authentication and detailed request body fields.

# Update an Existing Beneficiary

Edit an existing beneficiary stored on the Airwallex platform.

## Endpoint

`POST /api/v1/beneficiaries/{id}/update`

## Request Headers

- `Authorization` (string, required)
  Obtain a token via `POST /api/v1/authentication/login` with your API key and client unique identifier. Pass it as `Authorization: Bearer {{ACCESS_TOKEN}}`. Tokens expire after a configurable duration.

## Request Parameters

### Path Parameters

- `id` (string, format: uuid, required)
  id of the beneficiary contact to update.

### Request Body

- `beneficiary` (object, required)
  Details of the beneficiary.
  - `additional_info` (object, optional)
    Additional information about the beneficiary.
    - `business_area` (string, optional)
      Category of business activity.
    - `business_phone_number` (string, optional)
      Business phone number.
    - `business_registration_number` (string, optional)
      Business registration number.
    - `external_identifier` (string, optional)
      The identifier that you use to identify a beneficiary, usually a unique identifier. This field can be used to link transfers or beneficiaries to other records such as tax form details for filing purposes.
    - `legal_rep_bank_account_number` (string, optional)
      Legal representative's personal bank account number used for declaration purposes. No funds will be sent to this account number.
    - `legal_rep_first_name_in_chinese` (string, optional)
      Legal representative first name in chinese.
    - `legal_rep_id_number` (string, optional)
      Legal representative id number.
    - `legal_rep_last_name_in_chinese` (string, optional)
      Legal representative last name in chinese.
    - `legal_rep_mobile_number` (string, optional)
      Legal representative’s mobile number associated with their bank account.
    - `personal_email` (string, optional)
      Personal email.
    - `personal_first_name_in_chinese` (string, optional)
      Beneficiary's first name in Chinese.
    - `personal_id_number` (string, optional)
      Personal unique identifier number.
    - `personal_id_type` (string, optional)
      Personal unique identifier type.
    - `personal_last_name_in_chinese` (string, optional)
      Beneficiary's last name in Chinese.
    - `personal_mobile_number` (string, optional)
      Personal mobile number.
    - `recipient_account_id` (string, optional)
      Account unique identifier of the recipient account used for payout processing. The account must be active and have `customer_agreements.terms_and_conditions.service_agreement_type` set to `RECIPIENT` (verify via [Retrieve account details API](https://www.airwallex.com/docs/api/scale/accounts/detail.md)).
    - `security_question` (string, optional)
      Security question. Required when the email address is not registered with Interac e-Transfer autodeposit.
    - `security_question_answer` (string, optional)
      Security question answer. Required when the email address is not registered with Interac e-Transfer autodeposit.
  - `address` (object, optional)
    Beneficiary's address details.
    - `city` (string, optional)
      Beneficiary's city.
    - `country_code` (string, optional)
      Beneficiary's country code (2-letter ISO 3166-2 country code).
    - `postcode` (string, optional)
      Beneficiary's post code.
    - `state` (string, optional)
      Beneficiary's state.
    - `street_address` (string, optional)
      Beneficiary's street address.
  - `bank_details` (object, optional)
    Beneficiary's bank account details where the payment will be credited.
    - `account_currency` (string, required)
      Account Currency.
    - `account_name` (string, required)
      Account holder name of the beneficiary’s bank account.
    - `bank_country_code` (string, required)
      Bank country code (2-letter ISO 3166-2 country code).
    - `account_name_alias` (string, optional)
      The beneficiary’s account name known in the payment system. This is only supported in some regions and transfer methods. See detailed definitions in the [Payouts Product Docs](https://www.airwallex.com/docs/payouts/beneficiaries/create-beneficiaries.md).
    - `account_number` (string, optional)
      Account number, mostly for non-european countries, either account_number or iban should be filled.
    - `account_routing_type1` (string, optional)
      Routing code type.
    - `account_routing_type2` (string, optional)
      Routing code sub type.
    - `account_routing_value1` (string, optional)
      Routing code value.
    - `account_routing_value2` (string, optional)
      Routing code sub type value.
    - `bank_account_category` (string, optional)
      bank account type.
    - `bank_branch` (string, optional)
      Specific branch of bank account.
    - `bank_name` (string, optional)
      Bank name of the beneficiary's bank account.
    - `bank_state` (string, optional)
      Bank State.
    - `bank_street_address` (string, optional)
      Bank street address.
    - `binding_mobile_number` (string, optional)
      The mobile number tied to the Beneficiary's bank account.
    - `fingerprint` (string, optional)
      Fingerprint of current beneficiary's bank account.
    - `iban` (string, optional)
      International bank account number, mostly for european countries.
    - `intermediary_bank_name` (string, optional)
      Bank name of the beneficiary's intermediary bank.
    - `intermediary_bank_swift_code` (string, optional)
      Intermediary bank SWIFT code / BIC,Should contain alphanumeric characters only, Should be a valid and supported SWIFT code / BIC.
    - `local_clearing_system` (string, optional)
      Which clearing system should be used for this local bank transfer.

      Please refer to our [payout guide](https://airwallex.com/guides/payout) for details about each option.

      We suggest explicitly specifying this value, however if it's not provided we will select a default (using the specified account routing type and/or what's most often the best option).
    - `swift_code` (string, optional)
      Bank swift code.
  - `card` (object, optional)
    Beneficiary's card details where the payment will be credited.
    - `cardholder_name` (string, required)
      Cardholder name.
    - `token` (string, required)
      Tokenised card number, which can be retrieved from Airwallex beneficiary component.
    - `brand` (string, optional)
      Card brand.
    - `currency` (string, optional)
      Card currency.
    - `expiry_month` (string, optional)
      Expiry month.
    - `expiry_year` (string, optional)
      Expiry year.
    - `number` (string, optional)
      Card number.
  - `company_name` (string, optional)
    Company name of the beneficiary.
  - `date_of_birth` (string, optional)
    beneficiary date of birth.
  - `digital_wallet` (object, optional)
    Beneficiary's digital wallet details where the payment will be credited.
    - `account_name` (string, required)
      Account holder name of the beneficiary’s digital wallet.
    - `id_type` (string, required)
      Account identifier type of the beneficiary’s digital wallet.
    - `id_value` (string, required)
      Account identifier value of the beneficiary’s digital wallet.
    - `provider` (string, required)
      Service provider of the beneficiary's digital wallet.
    - `country_code` (string, optional)
      Digital wallet country code (2-letter ISO 3166-2 country code).
  - `entity_type` (string, optional)
    Entity type of the beneficiary.
  - `first_name` (string, optional)
    First name of the beneficiary.
  - `last_name` (string, optional)
    Last name of the beneficiary.
  - `stablecoin_wallet` (object, optional)
    - `address` (string, required)
      Blockchain wallet address of the beneficiary. Sending stablecoins to an incorrect wallet address or unsupported network will result in the irreversible loss of funds. Always verify the recipient wallet address and network before initiating a transfer.
    - `asset` (string, required)
      Stablecoin asset type, e.g., `USDC`.
    - `network` (string, required)
      Blockchain network, e.g., `ETHEREUM`.
  - `type` (string, optional)
    Type of the beneficiary, indicating the type of account or method through which the beneficiary receives funds. Possible values: `BANK_ACCOUNT`, `DIGITAL_WALLET`, `CARD`, `STABLECOIN_WALLET`.
- `transfer_methods` (array[string], required)
  Transfer method needs to be specified to ensure that accurate banking details are captured and validated for the specified transfer method. This is required for timely and accurate delivery of funds to the beneficiary account. Should be one of the following: `SWIFT`, `LOCAL`.
- `nickname` (string, optional)
  Nickname of the beneficiary.
- `payer_entity_type` (string, optional)
  The payer entity type that will be used for transfers being made to this beneficiary.  This is required to accurately capture and validate appropriate data for compliance reasons.  Defaults to `COMPANY`.
- `sca_exemptible` (boolean, optional)
  Whether the beneficiary can be exempted from SCA when applicable.
- `transfer_reason` (string, optional)
  Reason for the transfer instruction being made to this beneficiary.

Beneficiaries can be updated or deleted after creation using the Airwallex Payouts API. This covers the update and delete operations, including supported fields and example requests.

# Manage beneficiaries

You can perform the following operations on beneficiaries after you have created them.

## Update a beneficiary

After a beneficiary is created, you can call [Update existing beneficiary](https://www.airwallex.com/docs/api/payouts/beneficiaries/update.md) to update the saved beneficiary information. Specify the `beneficiary_id` in the endpoint URL and parameters you wish to update in your request body. The same schema validation and response body as in [Create a new beneficiary](https://www.airwallex.com/docs/api/payouts/beneficiaries/create.md) will apply.

The list of parameters that can be updated:

- `transfer_methods`
- `nickname`
- `beneficiary.date_of_birth`
- `beneficiary.address`
- `beneficiary.bank_details`
- some fields inside `beneficiary.additional_info`
  - `business_phone_number`
  - `business_registration_number`
  - `legal_rep_first_name_in_chinese`
  - `legal_rep_last_name_in_chinese`
  - `legal_rep_id_number`
  - `legal_rep_mobile_number`
  - `legal_rep_bank_account_number`
  - `personal_email`
  - `personal_id_number`
  - `personal_id_type`
  - `personal_mobile_number`

### Example request

```shell
curl -X POST https://api.sandbox.airwallex.com/api/v1/beneficiaries/{{BENEFICIARY_ID}}/update \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer {{ACCESS_TOKEN}}' \
  -d '{
    "address": {
      "city": "Seattle",
      "country_code": "US",
      "postcode": "98104",
      "state": "Washington",
      "street_address": "412 5th Avenue"
    }
  }'
```

If you are registered as a platform account, you can call this endpoint on behalf of your connected accounts by specifying the open ID in the `x-on-behalf-of` header.

## Delete a beneficiary

Call [Delete existing beneficiary](https://www.airwallex.com/docs/api/payouts/beneficiaries/delete.md) to delete a beneficiary. Specify the `beneficiary_id` in the endpoint URL. A successful deletion returns `true` in the response.

### Example request

```shell
curl -X POST https://api.sandbox.airwallex.com/api/v1/beneficiaries/delete/{{BENEFICIARY_ID}} \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer {{ACCESS_TOKEN}}'
```

If you are registered as a platform account, you can call this endpoint on behalf of your connected accounts by specifying the open ID in the `x-on-behalf-of` header.

The List all Beneficiaries API endpoint retrieves a paginated list of beneficiaries with optional filters. This covers the endpoint URL, authentication header, query parameters, and a cURL example.

# List all Beneficiaries

Get list of beneficiaries with optional filters on from date/time, to date/time, names and entity type. Results are paginated, with default list limit of 50 results.

## Endpoint

`GET /api/v1/beneficiaries`

## Request Headers

- `Authorization` (string, required)
  Obtain a token via `POST /api/v1/authentication/login` with your API key and client unique identifier. Pass it as `Authorization: Bearer {{ACCESS_TOKEN}}`. Tokens expire after a configurable duration.

## Request Parameters

### Query Parameters

- `bank_account_number` (string, optional)
  Filter on bank account number of beneficiary.
- `company_name` (string, optional)
  Filter on company name of beneficiary.
- `entity_type` (string, optional)
  Filter on entity type of COMPANY or PERSONAL.
- `from_date` (string, format: date-time, optional)
  The start date of `created_at` in ISO8601 format (inclusive).
- `name` (string, optional)
  Filter on name of beneficiary.
- `nick_name` (string, optional)
  Filter on nickname of beneficiary.
- `page_num` (integer, format: int32, optional)
  Page number, starts from 0.
- `page_size` (integer, format: int32, optional)
  Number of results per page. Default value is 100.
- `sca_exemptible` (boolean, optional)
  Filter on SCA exemptible beneficiaries.
- `to_date` (string, format: date-time, optional)
  The end date of `created_at` in ISO8601 format (inclusive).
- `type` (array[string], optional)
  Type of the beneficiary, indicating the type of account or method through which the beneficiary receives funds, i.e., BANK_ACCOUNT, DIGITAL_WALLET, CARD, STABLECOIN_WALLET.

## cURL example

```bash
curl --request GET \
  --url 'https://api.sandbox.airwallex.com/api/v1/beneficiaries' \
  --header 'Authorization: Bearer {{ACCESS_TOKEN}}' \
  --header 'Content-Type: application/json'
```

## Next steps

### Save a beneficiary

You can choose to save beneficiary information in Airwallex's system or on your side (your own database) without creating beneficiaries with Airwallex. In this case you can use our Embedded Beneficiary component to generate beneficiary payloads, save them on your server in the manner you prefer, and directly use them to create payouts along with payout information when needed.

### Create  or update a beneficiary

Once the beneficiary payload is retrieved, you can [create a new beneficiary](https://www.airwallex.com/docs/api/payouts/beneficiaries/create.md) in Airwallex.

You can also use the beneficiary payload to [update a beneficiary](https://www.airwallex.com/docs/api/payouts/beneficiaries/update.md) that you have already saved with Airwallex. To do this, you must:

1. Retrieve current details of the beneficiary by calling either [Get list of beneficiaries](https://www.airwallex.com/docs/api/payouts/beneficiaries/list.md) or [Get a beneficiary by ID](https://www.airwallex.com/docs/api/payouts/beneficiaries/retrieve.md).
2. Pre-fill the retrieved beneficiary details as default values in the Embedded Beneficiary component. This allows users to see the current information and make necessary updates.
3. After the user updates the information using the Embedded Beneficiary component, call the `submit()` method to retrieve the updated details.
4. Send the updated beneficiary information back to your server and call [Update a beneficiary](https://www.airwallex.com/docs/api/payouts/beneficiaries/update.md) to update the beneficiary in Airwallex's system.

### Create a new transfer

With the beneficiary created, you can call the [Create a new transfer](https://www.airwallex.com/docs/api/payouts/transfers/create.md) endpoint with the `beneficiary_id` to create a payout. You can also create a new payout without creating a beneficiaries by directly using the beneficiary payload retrieved from the beneficiary form in your request. See [Create a transfer](https://www.airwallex.com/docs/payouts/transfers/create-a-transfer.md) to learn more about this endpoint.

**Please note that these API calls should only happen on the server side, a trusted environment.**

### Render payout experience for a beneficiary

If you also want to render an experience where you allow the user to specify amount, date etc. and view currency conversion rates and fees, you can consider using the [Embedded payout components](https://www.airwallex.com/docs/payouts/transfers/embedded-transfer-component.md).

### Test your integration

Build and test your integration in the [sandbox environment](https://www.airwallex.com/docs/developer-tools/sandbox-environment.md) first before going to production. Make sure to account for various success and error scenarios.

## Retrieve a list of beneficiaries

Call [Get list of beneficiaries](https://www.airwallex.com/docs/api/payouts/beneficiaries/list.md) to retrieve saved beneficiary information. You can specify the time period when the beneficiary was created (`from_date`, `to_date`) and the pagination parameters (`page_num`, `page_size`) to refine the results. You can also use other filters such as `bank_account_number`, `company_name`, `entity_type`, and `nick_name`. The response will return a list of beneficiaries, each in the same manner as in the response body of [Create a beneficiary](https://www.airwallex.com/docs/api/payouts/beneficiaries/create.md).

```shell
curl -G https://api.sandbox.airwallex.com/api/v1/beneficiaries \

  --data-urlencode 'bank_account_number=string' \
  --data-urlencode 'entity_type=COMPANY' \
  --data-urlencode 'from_date=2017-04-01' \
  --data-urlencode 'name=Adam' \
  --data-urlencode 'nick_name=string' \
  --data-urlencode 'page_num=0' \
  --data-urlencode 'page_size=100' \
  --data-urlencode 'to_date=2030-01-01T00:00:00+0000'
```
